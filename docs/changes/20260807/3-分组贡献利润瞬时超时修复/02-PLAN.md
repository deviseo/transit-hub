# 分组贡献利润瞬时超时修复计划

## 根因

`GroupUsageToday` 在任一上游站点 key/token 成本查询失败时按既有保护逻辑返回 `profitAvailable=false`。运行态只读探测确认，当前已连接的上游中存在可在后续请求成功的瞬时超时，因此一次抖动会让整张利润图不可用。

## 实施

1. 为 key/token 用量查询加入固定次数、固定时限的重试，不提高现有并发。
2. 重试耗尽后保留原有 fail-closed 语义和错误路径。
3. 先补覆盖“首次失败、后续成功”的红灯测试，再实现并运行定向回归。
4. 按固定端口流程重启前后端，核对健康状态、监听归属和数据基线。

## 风险与回滚

- 瞬时失败时会增加一次受限的上游读取；固定时限和并发上限限制其影响。
- 若出现持续故障，仍显示利润不可用，不产生伪利润；移除重试调用即可回到原行为。
