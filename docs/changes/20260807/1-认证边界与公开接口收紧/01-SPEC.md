# 认证边界与公开接口收紧

## 目标 / 需求快照

本次修复整盘 review 已确认的公开接口问题：未登录可读取用户列表，未配置 CORS 时任意来源可读取响应，后端保留前端不可达的注册和占位登录接口。

## 成功标准

- `/api/users` 进入现有 TransitHub 登录鉴权。
- 未配置 `CORS_ORIGINS` 时不返回跨域许可；只有明确列入允许清单的来源才返回 CORS 凭据头。
- 后端只保留真实的 `POST /api/auth/login` 登录入口；注册、验证码、占位密码登录和占位 API Key 登录接口不再注册。
- 前端删除已经不可达的注册页、注册请求和注册类型死代码。
- 新增自动化回归测试，先复现旧行为，再证明修复生效。

## 明确不做

- 不接入新的 SMTP 或验证码发送链路。
- 不改变现有邮箱密码登录、会话令牌和工作区数据流。
- 不删除或修改现有数据库表和数据。
- 不提交 Git，不改动用户已有的三处未提交修改。

## 固定约束

- 修复复用现有 `protectedPath`、`cors` 和路由注册方式，不新增第二套鉴权中间件。
- 前端 `/register` 已重定向到 `/login`，删除死代码不改变当前可达页面行为。
- 本轮完成后必须重启固定开发服务 `5444` 和 `5555`，再运行受控全量测试和二次 review。
