# 前端测试基线与构建门禁

## 目标 / 需求快照

整盘 review 确认前端只有 1 个 Node 测试文件、5 个用例，且构建依赖存在可修复高危告警，仪表盘入口产物超过默认体积告警线。本次建立最小可重复前端测试基线，并修复已确认的依赖与构建门禁问题。

## 成功标准

- 前端有固定的受限并发测试命令，可执行 TypeScript 测试且不启动端口或浏览器。
- 原有利润率测试迁移到固定测试命令，真实登录 API 成功与失败路径有回归测试。
- `npm audit` 不再报告已确认的 `postcss`、`brace-expansion` 告警。
- ECharts 从仪表盘入口独立分包，生产构建不再给 `DashboardView` 报超过 500 kB 的告警。
- 既有 4 个 Go 格式问题清理，`gofmt -l` 无输出。

## 明确不做

- 不建立浏览器 E2E、CI 门禁或全仓覆盖率阈值。
- 不改变仪表盘功能、懒加载路由或组件视觉行为。
- 不升级无关的直接依赖，不修改用户已有未提交文件。

## 固定约束

- 测试最多使用 2 个 worker，不开端口、不访问真实外部服务。
- 依赖下载使用现有锁文件的国内镜像 `registry.npmmirror.com`。
- 构建分包只使用 Vite/Rollup 现有配置，不引入新构建工具。
